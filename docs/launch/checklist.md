# Launch checklist

Last updated: 2026-10-30

This is the one ordered list of everything the owner does by hand to take Habitués (Android, package `fr.habitues.app`) from the repository to the Play Store. The code does not need anything else. Each step links to the document that has the details. Do the steps in this order: later steps depend on earlier ones (for example the signing fingerprint exists only after the Play developer account and the first build).

Conventions: `<WEB_BASE_URL>` is the public address of the site, without a trailing slash. A box marked "Done" is yours to tick. Never paste a secret into a document, a chat or a CI log.

Release 1 contains no ads, no private messages, no badges and no iPhone app. Sign-in is by an 8-digit e-mail code or Google, with no passwords.

## Part A. Hosted project and site

1. [ ] **Domain.** Buy a domain and add it to the Pages project as a custom domain, with DNS on Cloudflare. A custom domain is needed because the Cloudflare Cache API does nothing on `*.pages.dev`, and the rate limit in step 9 only makes sense with it. See [Domain and Cloudflare settings](../../README.md#2-domain-and-cloudflare-settings-spec-185).
2. [ ] **Supabase Pro, Paris region.** Create the production project on the Pro plan (daily backups) in the Paris region (`eu-west-3`; the RGPD register says the data is hosted in the EU, Paris). Region cannot be changed later. See [Where the backups are](../ops/backup-restore.md#1-where-the-backups-are) and [Supabase in the processors list](../rgpd/sous-traitants.md#supabase). Decide now whether to buy point-in-time recovery.
3. [ ] **`supabase db push`.** Link the CLI to the hosted project and push every migration (up to the latest one). Then check by hand in the SQL editor that the Auth triggers from the security review exist (`on_auth_user_created`, and the password-blanking trigger on `auth.users`), and that `select jobname, active from cron.job` lists the scheduled jobs. Apply the large `associations` migration outside import runs: see [Hosted migration note](../../README.md#hosted-migration-note). Deploy migration 43 and the website together: the sitemap functions depend on its signature. Then run the importer once: see [First run](../../README.md#first-run).
4. [ ] **Vault secrets and cron.** Create the Vault secrets `send_push_key`, `send_push_url` and `storage_cleanup_url`, so that the `drain-outbox` and `storage-cleanup` jobs do something. Without them queued notifications and queued file deletions (including replaced avatars) never run. See [Database secrets and the send-push function](../../README.md#database-secrets-and-the-send-push-function), [Scheduled jobs](../../README.md#scheduled-jobs-pg_cron) and [Retention schedule](../../README.md#retention-schedule).
5. [ ] **Edge Functions and their secrets.** Deploy `send-push`, `storage-cleanup` and `submit-feedback`. Set the function secrets `TURNSTILE_SECRET`, `ALLOWED_ORIGINS=https://<site>` and `TURNSTILE_HOSTNAMES=<site host>,challenges.cloudflare.com`. Test the cron calls and an anonymous and a signed-in feedback call after deploying. See [Deploying the functions and their secrets](../../README.md#deploying-the-functions-and-their-secrets) and the review's [owner actions](../security/2026-11-review.md#owner-actions-on-the-hosted-project), items 12 and 13.
6. [ ] **Auth settings and TOTP.** Apply every setting in [Supabase Auth settings](../../README.md#3-supabase-auth-settings-dashboard): confirm e-mail ON, secure password change ON, secure email change ON, OTP length 8 and expiry 600 s, both e-mail templates with `Votre code Habitués : {{ .Token }}` and no link, rate limits of 10 token verifications, 15 sign-ups and sign-ins and 100 token refreshes per 5 minutes per IP, the e-mail rate limit set to what the SMTP provider allows, sign-up ON, anonymous sign-ins OFF, manual linking OFF, phone OFF, JWT expiry 3600 s or less, refresh-token rotation ON with a 10-second reuse interval, CAPTCHA with the Turnstile secret, custom SMTP. Only the Google provider is on, with "Skip nonce check" ON (accepted risk AUTH-6; without it native Google sign-in fails). Redirect URLs: exact addresses only, no wildcard. Turn TOTP enrolment and verification ON, then promote the first admin with the person's phone at hand and check `auth.mfa_factors` straight afterwards: see [Making the first admin](../../README.md#making-the-first-admin). In the API settings, "Exposed schemas" stays `public` and `graphql_public` only, never `private`, `net`, `vault` or `cron`. After this step and after every deploy:
   - [ ] CAPTCHA check: call `POST <SUPABASE_URL>/auth/v1/otp` with the anon key and no `captcha_token`, and expect a `captcha` error (WEB-8).
   - [ ] Password check: run `curl -s -o /dev/null -w "%{http_code}" -X POST "<SUPABASE_URL>/auth/v1/token?grant_type=password" -H "apikey: <anon key>" -H "Content-Type: application/json" -d '{"email":"nobody@example.com","password":"x"}'` and expect `400`. The smoke script does not check this (see step 18).
7. [ ] **Google OAuth clients.** Create the Web client (its id and secret go into Supabase and into `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`), and an Android client for the new package `fr.habitues.app` with the signing SHA-1 (re-created: a client made for the old package `fr.friendapp.app` does not work). Add the Play app-signing SHA-1 after step 15. See [Google sign-in](../../README.md#1-google-sign-in-free-no-billing-account).
8. [ ] **Firebase.** Create the Firebase project and add an Android app with the package `fr.habitues.app` (re-created, not reused from the old package). Put `google-services.json` in the EAS file secret `GOOGLE_SERVICES_JSON` and upload the FCM V1 key in EAS credentials. See [Firebase and google-services.json](../../README.md#firebase-and-google-servicesjson-android-push) and [Expo push credentials](../../README.md#expo-push-credentials).
9. [ ] **Cloudflare Pages, DNS, DNSSEC, WAF and rate limits.** Create the Pages project and set its variables, including `NODE_VERSION=22`, `WEB_BASE_URL` on Production and also on Preview (the robots.txt guard needs it), and the Functions failure mode "Fail open". Then, in Cloudflare: Always Use HTTPS, DNSSEC with the DS record at the registrar, WAF managed rules ON with no challenge on the public pages, the rate-limit rule (60 requests per 10 seconds per IP on `/activites/*`, `/associations/*`, `/sitemaps/*` and `/app/*`, block for 10 minutes: the only real cap on made-up page ids), and Cloudflare Access on preview deployments. For an urgent takedown of a page removed by moderation (WEB-6), purge its URL in Caching, Configuration, Purge Cache, Custom purge: the edge cache otherwise serves it for up to 5 minutes. See [Create the Cloudflare Pages project](../../README.md#1-create-the-cloudflare-pages-project), [Domain and Cloudflare settings](../../README.md#2-domain-and-cloudflare-settings-spec-185) and the review's [owner actions](../security/2026-11-review.md#owner-actions-on-the-hosted-project), items 14 to 18.
10. [ ] **Turnstile hostnames.** In the Turnstile widget (mode Invisible) allow the site's hostname and `challenges.cloudflare.com`. See [Turnstile (web)](../../README.md#4-turnstile) and [Cloudflare Turnstile](../../README.md#2-cloudflare-turnstile-free).
11. [ ] **GitHub settings.** Dependabot alerts, secret scanning with push protection, CodeQL, restricted Actions permissions, the branch ruleset on `main` with its required checks, and two-factor sign-in on the owner account. See [GitHub settings guide](../ops/github-settings.md).

## Part B. Legal

12. [ ] **Processor DPAs.** Accept the data processing agreement of Supabase, Cloudflare, Google (Firebase), Expo and GitHub, then note the date and where the copy is kept in the table. See [Suivi des accords](../rgpd/sous-traitants.md#suivi-des-accords).
13. [ ] **Publisher identity and `PRIVACY_CONTACT`.** Fill in the publisher name, address and contact, and the hosts, in the "Mentions légales" and the terms (`web/src/legal.ts`), and in the controller line of the RGPD register (`docs/rgpd/registre-des-traitements.md`). Replace the placeholder `PRIVACY_CONTACT` in `app/src/content/contact.ts` (`confidentialite@<domaine>`) with a real mailbox: it is the address for privacy requests, for contesting a moderation decision, and the contact e-mail of the store listing. Also replace the placeholder privacy address in the privacy texts. See [Before launch](../../README.md#before-launch), [Before launch (web)](../../README.md#6-before-launch) and [Before publication](../../README.md#5-before-publication).
    - [ ] **Consumer mediator.** Designate a consumer mediator (Code de la consommation, article L.616-1) and name it in the terms (the CGU in `web/src/legal.ts` currently only says that a mediator exists).
14. [ ] **Legal review.** Have a qualified person review the privacy texts (`app/src/content/privacy.fr.ts` and `privacy.en.ts`), the terms and the "Mentions légales", and the RGPD documents (`docs/rgpd/`). Ask them to consider separating the privacy notice from the terms. Tell them that `export_my_data` now exports the avatar object name (a random storage name, not a URL), so the RGPD documents may need one sentence about it (not yet in `docs/rgpd/`). Known follow-up: the `search_misses` table has no retention job yet; settle it with the reviewer before launch or accept it in writing.

## Part C. Play Console and build

15. [ ] **Play developer account.** Create it (one-time fee of $25) and complete identity verification, which can take days. Create the app Habitués with the package `fr.habitues.app`, and fill in the store pages: listing text in [store-listing.fr.md](store-listing.fr.md) (screenshots, [feature graphic](feature-graphic.png)), the data safety form from [data-safety.md](data-safety.md), the rating from [content-rating.md](content-rating.md), the privacy policy URL `<WEB_BASE_URL>/confidentialite`, the account deletion URL `<WEB_BASE_URL>/app/profile`, and the contact e-mail. Before publishing the listing, confirm the hosted import count (the listing says "des centaines de milliers d'associations"; check the number of rows in the hosted `associations` table after the first import, and adjust the sentence if it is below 100,000). The account deletion page `/app/profile` shows the Profil screen with a "Se connecter" button when signed out and, after Google or e-mail-code sign-in, returns to the same page; open it signed out once to confirm.
16. [ ] **EAS build.** Set the build variables in the EAS `production` environment, notably `EXPO_PUBLIC_WEB_BASE_URL` (the production profile fails to build without it), `EXPO_PUBLIC_PLAY_STORE_URL`, `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`, `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`, `EXPO_PUBLIC_TURNSTILE_SITE_KEY` and `GOOGLE_SERVICES_JSON`. Build with `npx eas-cli build -p android --profile production`. Then, before uploading the bundle:
    - [ ] Run `apkanalyzer manifest permissions` on the `.aab` and check that the blocked permissions (microphone, advertising ID, camera, calendar, external storage, overlay, fine location) are absent.
    - [ ] Smoke-test on a real device with the build that will be uploaded: location (approximate only), add to calendar, the photo picker and the document picker.
    See [Release build](../../README.md#release-build).
17. [ ] **Signing SHA-256 into the website, then redeploy.** In Play Console, "App integrity", copy the SHA-256 of the app signing key certificate and put it in the Pages variable `ANDROID_SHA256_CERT` (the web build reads that name; the plan called it `ANDROID_SHA256_FINGERPRINTS`), then redeploy the site. Add the matching SHA-1 to the Android OAuth client of step 7. Check the Digital Asset Links answer lists `fr.habitues.app` and the fingerprint. See [After the first deploy](../../README.md#5b-after-the-first-deploy) and [Release build](../../README.md#release-build).
18. [ ] **Smoke check, after every deploy.** Run `npm run smoke` with `SMOKE_WEB_BASE_URL`, `SMOKE_SUPABASE_URL` and `SMOKE_SUPABASE_ANON_KEY` set in your shell. Every line must say `ok`. Also check the link preview of an activity page in WhatsApp. See [After the first deploy](../../README.md#5b-after-the-first-deploy).
19. [ ] **Restore test.** Run the restore check against the hosted backup and write a line in the restore test table. Do it before the closed test ends and then every quarter. See [Prove a backup works](../ops/backup-restore.md#3-prove-a-backup-works-the-restore-check) and [Restore tests](../ops/backup-restore.md#4-restore-tests). Also confirm the migrations are all there after the restore and that `select jobname, active from cron.job` lists the jobs.

## Part D. Release

20. [ ] **Closed test for 14 days.** Create the closed track, invite at least 12 testers (aim for 15 to 20), count 14 consecutive days from the day the twelfth tester joined, and read the feedback every week. See [closed-test.md](closed-test.md). Re-run steps 18 and the grant_type check of step 6 after any redeploy during the test.
21. [ ] **Production release.** After the 14 days, in Play Console apply for production access, then create the production release from the tested bundle with a staged rollout (start at 20 percent). Watch Android vitals, the Auth logs for 429 responses (carrier-shared IP addresses; raise the per-IP limits if real people are blocked) and the feedback queue for the first week. Read [Rollback](#rollback) before pressing "Publish".
22. [ ] **Search Console sitemap.** Add the domain property in Google Search Console and submit `<WEB_BASE_URL>/sitemap.xml`. See [Search engines](../../README.md#5-search-engines).

## Rollback

Use the smallest tool that fixes the problem.

1. **A bad app release (staged rollout).** In Play Console, open the production release and choose "Halt rollout". People who already have the new version keep it; nobody new gets it. Fix the problem, build a new bundle (EAS raises the version code itself) and release again. A halted release cannot be "rolled back" to the old file; publish the fix as a new release.
2. **A bad website deployment.** In Cloudflare, Workers and Pages, the project, "Deployments": pick the previous good production deployment and "Rollback to this deployment". Then run `npm run smoke`. If the problem is only a stale page, purge that URL in Caching, Configuration, Purge Cache.
3. **A bad database change.** Write a new migration that fixes it. Never edit or delete a migration that was pushed. Do not restore a backup for a change that a new migration can undo.
4. **Last resort: restore a backup.** Only for real data loss or corruption. Restoring replaces the live database and loses everything written since the backup (accounts, messages), and Storage files are not in the backup. Follow [Restore a backup in the dashboard](../ops/backup-restore.md#2-restore-a-backup-in-the-dashboard), then re-check the cron jobs and the Vault secrets, run `npm run smoke`, and tell people what was lost. If personal data was exposed, follow `docs/rgpd/violation-de-donnees.md` (72-hour notification clock) and write it in `docs/rgpd/journal-des-incidents.md`.
